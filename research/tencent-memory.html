Tencent · Agent Memory

让 Agent 记住该记的，
而不是把上下文塞满。

腾讯的 Agent Memory 拒绝两件事：把历史一股脑堆进上下文，以及把它压缩成无法回溯的摘要。

02 两个核心想法

不是新发明的算法，而是两个工程哲学。

分层 · Layering

记忆不应是平的

把对话拆成四层金字塔：原文 → 原子事实 → 场景 → 画像。上层做判断，下层做证据，需要细节时再下钻。

符号化 · Symbolic

用最少的符号承载语义

长任务的日志卸载到外部文件，上下文里只留一张 Mermaid 画布。Agent 读图，按 node_id 回查原文。

05 同一套思路，三处复用

分层不只是给"长期记忆"用，三个维度都按这个范式走。

◐

短期上下文

底层 refs/*.md 存原始工具输出；中层 JSONL 是步骤摘要；顶层 Mermaid 在上下文里。

◑

长期个性化

L0 对话 → L1 原子 → L2 场景 → L3 画像。日常用 Persona，需要细节时下钻。

◒

技能生成

从执行轨迹（Conversation）里提取解法（Scenario），再蒸馏出可复用的 Skill / SOP。

07 常见疑问

三个最容易混淆的点。

为什么不直接用向量库？
向量库把记忆"摊平"成一堆碎片，召回时只能盲搜，没有宏观结构。腾讯的做法是先建金字塔（Persona/Scenario 给方向），再下钻到向量层取证据 —— 检索从"撞概率"变成"按路径走"。
Mermaid 不是给人看的吗？为什么 Agent 也能读？
Mermaid 语法简洁、节点关系明确，对 LLM 来说比 JSON 更省 token、比自然语言更结构化。一张图既能给人看，也能直接进上下文。它是"高密度、低歧义"的中间表示。
L3 Persona 万一错了怎么办？
所有上层都不是黑盒：Persona 是 Markdown 文件，能直接打开看；每条画像都能追溯到生成它的 Scenario 和 Atom。调试不再是"猜向量分数"，而是沿着 Persona → Scenario → Atom → Conversation 走一遍。
